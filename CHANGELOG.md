## [5.76.0] — 2026-06-01 — Soundness fuzzing, broadened to the comparison gadget — and the correct "wrong proof" invariant
- **Fuzzing the riskiest lowering.** The fuzzer now generates two families — arithmetic *and* comparison/boolean control flow (`< > <= >=`, `&&`/`||`/`!`, `if`) — exercising the hand-vetted-but-never-fuzzed **comparison gadget** on random operands. `python3 fuzz/fuzz_soundness.py 8 7`.
- **The correct soundness invariant.** A wrong proof is **an ACCEPT the independent reference interpreter does not confirm** — *not* "anything that isn't ACCEPT." **ABSTAIN** (the gadget refusing an out-of-range/unlowerable program) and **REJECT** (a disproof) are *sound* outcomes; only a wrong ACCEPT is a violation. The fuzzer's pass condition was corrected to match (it had over-counted ABSTAINs as failures).
- **Result: the prover held up.** Across the random batch — 6 ACCEPT (every one reference-confirmed), 2 correct ABSTAINs (the gadget refusing negative operands like `a-3 = -2`, outside its provable `[0, 2³²)` range), **0 wrong proofs.** The comparison gadget refuses out-of-range inputs rather than ever wrongly accepting — the soundness property holding under fuzzing. Suite **418/418** unchanged (the fuzzer is a standalone on-demand tool). Research/educational-grade, UNAUDITED.

## [5.75.0] — 2026-06-01 — Soundness fuzzing — and the over-strict Third Witness it caught on its first run
- **Differential soundness fuzzing.** New [`fuzz/fuzz_soundness.py`](fuzz/fuzz_soundness.py) generates random small arithmetic Glass programs over private inputs, proves each with `glass prove --witness3`, and asserts the soundness invariants across the whole stack at once: honest → ACCEPT, and **THIRD LINEAGE AGREES** (the bridge's circuit semantics equal the reference interpreter's). This is the testing that finds bugs the enumerated 13-case gate cannot. `python3 fuzz/fuzz_soundness.py [N] [seed]`.
- **It earned its keep immediately.** The first run flagged `((4+c)*((c-b)*(8-a))) = -560` as a witness3 DIVERGENCE — but that was an **over-strictness in the Third Witness**, not a proof bug: the bridge reports a field element (`p-560 = 18446744069414583761`) while the interpreter reports the int64 `-560` — the *same value*, different representations. witness3 compared them *exactly* instead of **modulo the Goldilocks prime**, so it false-diverged on every negative result.
- **The fix.** `glass prove --witness3` now reconciles the two results **mod p** — correct for small/negative results (a negative matches its field form) while still flagging a *genuine* domain divergence (e.g. an int64 multiply that wraps mod 2⁶⁴ where the field wraps mod p, which now reads "differ even modulo the prime — worth investigating"). With the fix, the fuzz batch passes (4/4 ACCEPT + AGREE). Suite **418/418**; the in-circuit-Merkle case still diverges (correctly — its large hash products genuinely differ mod-2⁶⁴ vs mod-p). Research/educational-grade, UNAUDITED.

## [5.74.0] — 2026-06-01 — Portable proofs: `glass prove --emit` + `glass verify` — prove once, verify anywhere with the independent second verifier
- **The proof becomes a portable artifact.** `glass prove --emit <file>` serializes a real `ProofB3` (via the v5.64 `emit_proofb3`) to a token-stream file; `glass verify <file>` checks it with the **independent** Python verifier (`pentecost/`, plain int mod p, no Glass code). This operationalizes "let the verifier be two" as a CLI workflow: the proving side and the checking side are separate programs, separate lineages.
- **Validated.** `glass prove --emit /tmp/p.txt "a + b" a=3 b=5` → a 154,842-token proof; `glass verify /tmp/p.txt` → **PENTECOST: ACCEPT**; a one-token tamper → **REJECT** (gate-identity FAIL). The emit/verify mechanism is the same one `pentecost/difftest.sh` gates; the keystone is suite-gated. Suite **418/418** (additive CLI; no behavior change to existing paths).
- **Composes with the suite of primitives.** A portable proof can be recorded in the Preserved Tablet (`glass tablet`), its toolchain fingerprinted by the Name (`glass name`), and its source semantics cross-checked by the Third Witness (`glass prove --witness3`). Research/educational-grade, UNAUDITED.

## [5.73.0] — 2026-06-01 — Tzimtzum-as-a-type: `Concealed<T>` — a value provable-about but never observable, enforced at compile time (north-star direction, shipped)
- **Privacy as a type, by construction.** `conceal : T -> Concealed<T>` withdraws a value behind an **opaque** type; `cmap : (Concealed<T>, T->U) -> Concealed<U>` computes *within* concealment (the result stays concealed); `concealed_in_range : (Concealed<Int>, Int, Int) -> Bool` proves a property and returns a **public** Bool. The witness stays hidden as a *compile-time* guarantee.
- **The cut: privacy by the absence of a reveal eliminator.** `Concealed<T>` is a known parametric type with **no constructor and no operation that returns the underlying `T`** — so a concealed value can *never* reach an observable position. Every reveal attempt is a type error, not a convention: `conceal(5) + 1` → "got Concealed<Int>"; `print(conceal(5))` → arg mismatch; `match conceal(5) { Conceal(x) => x }` → "unknown constructor 'Conceal'" (it is structurally unopenable). Even debug output shows `<concealed>`, never the value.
- **Showcase + gates.** [`examples/conceal_showcase.glass`](examples/conceal_showcase.glass): conceal a salary, prove it's in a band and compute a raise on it — all without revealing it. Suite gains a positive (conceal + cmap + range-proof → public `true`) and two negatives (arithmetic and pattern-match reveals rejected). Suite **418/418**.
- **Honest scope.** This is Tzimtzum *as a type* — compile-time non-observability. Wiring concealed values to the actual ZK prover witness (so the hiding is cryptographic, not only type-level) is the continuing work. Reference-checker (`glass.py`) enforced; native-checker enforcement is a follow-up. Research/educational-grade, UNAUDITED.

## [5.72.0] — 2026-06-01 — H3 milestone: in-circuit Merkle membership — a leaf authenticated to its root by hashing UP THE PATH inside the proven circuit
- **The recursive verifier's missing primitive, demonstrated.** H3 (a proof that verifies another proof) needs the verifier to authenticate opened values against a commitment *inside* the circuit — in-circuit Merkle membership. The roadmap had "the fold-check-as-circuit is done; composing it with in-circuit Merkle membership hasn't shipped." Now it has: [`examples/prove/merkle_member.glass`](examples/prove/merkle_member.glass) writes the path-hashing as an ordinary Glass program (x⁷ S-box + a 3×3 MDS mix — all `+`/`*`, which the bridge lowers to field gates), and `glass prove` turns it into a circuit. `glass prove merkle_member.glass leaf=42 s0=7 d0=0 s1=99 d1=1` → the public result **is the depth-2 Merkle root recomputed in-circuit** (ACCEPT, ~39s); leaf + siblings + directions stay private ("I know a leaf in the tree with root R", revealing only R).
- **The cut.** A hash is just `+`/`*`/`x⁷` — all already provable — so in-circuit membership is *written as Glass and lowered by the existing bridge*, not hand-built as a bespoke gadget. The membership is deterministic and **binding** (a different leaf or sibling yields a different root — suite-gated via the reference interpreter).
- **Honest scope.** This is the in-circuit-membership *primitive* at depth 2 with a reduced algebraic compression (the `prove_preimage_zk` pattern, kept small to dogfood). The *full* recursive verifier — full Poseidon2 per node, composing membership with the FRI fold-check, and ultimately `verify_b3`-as-a-circuit — remains open and is performance-gated (the comparison-gadget lesson: ~1000 gates ≈ 54s; a Merkle path of full Poseidon2 nodes needs a faster prover or a lookup argument). `--witness3` reports DIVERGENCE here — correctly: the hash's large products wrap differently mod-p (the bridge, the right domain) vs int64 (the interpreter), exactly the documented caveat. Suite **415/415**. Research/educational-grade, UNAUDITED.

## [5.71.0] — 2026-06-01 — The Third Witness: bind the proof's public result to an independent re-execution (the source↔circuit gap two verifiers can't see)
- **Cut the rope, not the knot.** `glass prove --witness3` re-executes `f(inputs)` under the **reference interpreter** (`glass.py` — a lineage independent of the prove bridge's Glass-level evaluator `heval` AND its circuit lowering `cgen`) and binds the proof's public result to it. The third verdict: *THIRD LINEAGE AGREES* (three lineages — bridge evaluator, proof circuit, reference interpreter — concur on the semantics) or *DIVERGENCE*.
- **The gap it closes.** The compiler fixpoint (`gen1==gen2`) proves the compiler is self-consistent; verifier-be-two proves `verify_b3` is correctly implemented. But **both verifiers verify the circuit** — if the bridge lowers `f` to a circuit computing `g≠f` (a bug shared by `heval` and `cgen`), the STARK is internally valid, both verifiers ACCEPT, and you'd believe you proved `f`. The Third Witness re-derives `f`'s result from a separate lineage and catches that. The radical cut: a third *evaluator* (reuse the interpreter that already exists) is vastly cheaper than a third *STARK verifier* — and catches exactly this class.
- **Honest scope.** This is the *semantic* third witness (binds the public output). The fuller "third independent verifier of the STARK construction itself" remains the open research bet. Caveat: the bridge computes over Goldilocks mod p, the interpreter over int64 — a divergence only on results that wrap differently is a semantics-domain difference, not a lowering bug. Validated: `glass prove --witness3 "a+b" a=3 b=5` → result 8, proof ACCEPT, *THIRD LINEAGE AGREES*. The evaluator logic is suite-gated (a+b=8, 3<5=1, 5<3=0); suite **414/414**. Research/educational-grade, UNAUDITED.

## [5.69.0] — 2026-06-01 — Poseidon2 (Plonky3), stage 0: a native `poseidon2_perm` intrinsic, byte-exact to Plonky3's published vectors

The Python port was checked against the vector before the C port. Bootstrap fixpoint re-verified (gen1==gen2, 1151 lines C — the new intrinsic landed as its own shallow `cpre_p2` prelude chunk to stay under clang's frontend recursion limit). Suite **412/412**.

## [5.68.0] — 2026-06-01 — Opening the Seals: selective disclosure over a blinded Poseidon commitment (north-star direction, shipped)
- **Reveal one field, hide the rest.** New `glass seal` ([`seal/`](seal/)) commits a record of named fields — each a **blinded** leaf `Poseidon(field ‖ value ‖ nonce)`, nonce derived from a secret seed — into a Poseidon-Merkle root. ## [5.67.0] — 2026-06-01 — The Urim's Silence: ABSTAIN as a third verdict — a refusal is never a disproof (north-star direction, shipped)
- **ACCEPT / REJECT / ABSTAIN.** `glass prove` now reports a distinct **ABSTAIN** when the prover *refuses to lower* a statement (an op with no faithful field lowering — `/`, `%`, strings; an out-of-range comparison; a parse/unroll failure) instead of conflating it with REJECT. A **REJECT** means `verify_b3` ran and the proof failed — a disproof of the claim. An **ABSTAIN** means Glass could not honestly form the claim at all. Conflating them is a real soundness-communication hazard ("REJECT" reads as "your statement is false"); the third verdict removes it.
- **Sound by construction.** The refusal aborts (the bridge's loud `error`) *before* `prove_b3`/`verify_b3` runs, so ABSTAIN structurally **cannot swallow a real REJECT** (different code path; REJECT is an exit-0 `proof: REJECT`, ABSTAIN is the refusal path). The out-of-range comparison messages are reworded `REJECT → ABSTAIN (cannot lower; not disproving)` to match.
- **Completes what the Tablet records.** [`ledger/`](ledger/) already logs all three verdicts; this makes the prover's own output speak the same trichotomy. Validated: `glass prove "a / b"` → `verdict: ABSTAIN`; honest claims still `proof: ACCEPT`. Soundness gate **13/13** (wording-only bridge change); suite **410/410**.

## [5.66.0] — 2026-06-01 — The Preserved Tablet: an append-only, tamper-evident ledger of proof verdicts (north-star direction, shipped)
- **Verdicts become a record.** New `glass tablet` ([`ledger/`](ledger/)) appends each proof verdict (`seq · statement · result · verdict`) to `ledger/LEDGER` and commits the history into a Poseidon-Merkle root (`ledger/ROOT`). No past entry can be altered, reordered, or dropped without changing the root; an **inclusion proof** (`glass tablet prove <i>` / `verify <i>`) shows a verdict is committed at a given root. Seeded with the verdicts validated in v5.62–v5.64 (the comparison gadget; the out-of-range ABSTAIN).
- **Same Poseidon, no new trust.** Built on `pentecost/poseidon.py` (Plonky2-exact) — a byte sponge per entry, Poseidon 2-to-1 Merkle over the leaves (odd nodes duplicate-last). The Tablet binds verdicts that already exist; it does not re-prove anything.
- **Gated.** `glass tablet --selftest` checks determinism, that inclusion proofs verify for every entry, that a forged entry does **not** verify against the root, and that tampering a past entry changes the root; the regression suite runs it. Suite **410/410**.
- **Honest scope.** Attests *what was claimed and how it was judged*, with tamper-evidence over the history — correctness is still the fixpoint + soundness gate + Pentecost differential. Research/educational-grade, UNAUDITED — *do not protect real value*.

## [5.64.0] — 2026-06-01 — Let the verifier be two: an independent non-Glass verifier checks real Glass proofs end-to-end (the #1 north-star direction; the deepest in-repo soundness upgrade)
- **`verify_b3` no longer stands alone.** Glass's native prover now **serializes** a real `ProofB3` (`emit_proofb3` in the bridge), and the from-scratch Python re-verifier [`pentecost/`](pentecost/) — plain `int mod p`, its own Poseidon, **sharing no Glass code** — parses and checks it. The end-to-end differential ([`pentecost/difftest.sh`](pentecost/difftest.sh)): **honest proof → ACCEPT in both Glass and Pentecost; tampered root / wrong claim / tampered opening → Pentecost REJECT.** This retires, for the B3 path, the honest-ledger caveat that `verify_b3` was "reasoned, not machine-checked."
- **The serializer, byte-for-byte with the reader.** `emit_proofb3` emits the exact token stream `pentecost_verify.parse()` consumes — every rep-reconciliation trap handled: a field element is `count` + base-2¹⁶ limbs; a **digest is the 4 Poseidon lanes** (`to_lanes`), not one 16-limb element; `TOpenB`'s 16 fields emit in the parser's order (incl. the root1/**root3**/root2 path order). On a trivial circuit the honest proof is 154,842 tokens, and Pentecost recomputes the same Fiat-Shamir transcript, OOD gate-identity, PLONK grand-product, and FRI from those values to reach ACCEPT.
- **What unblocked it.** The only remaining blocker was proof-gen speed; the v5.59–v5.62 prover cuts took a real proof from >18 min to seconds, so the differential is now runnable (a proof emits in ~25s and Pentecost checks it).
- **Honest scope (held).** Both verifiers are built from the **same public specs** — this catches implementation divergence in `verify_b3` (the bug class the `gen1 == gen2` compiler fixpoint structurally cannot), not a shared spec misreading. A truly independent oracle (the "Third Witness") and an external audit remain the standing boundary; research/educational-grade, UNAUDITED, *do not protect real value*. Soundness gate **13/13** (the serializer is purely additive); the bootstrap fixpoint is unaffected (glassc.glass untouched). Note: naive `++` token-building is O(N²) — fine for the differential's small circuit, a follow-up for 115k-token proofs.

## [5.62.0] — 2026-06-01 — Cut ropes 3 & 4: the ordering-comparison gadget LANDS — `glass prove "a < b"` goes from >18 min + segfault to ~54s, sound (`3<5`→1 ACCEPT, `5<3`→0 ACCEPT, out-of-range→loud REJECT)
- **The payoff.** Three releases of rope-cutting (Poseidon v5.60, NTT v5.61, and this one) finally land the vetted range-bounded comparison gadget (`<` `>` `<=` `>=`) in the default Goldilocks prover. `glass prove examples/prove/cmp_prove.glass a=3 b=5` → **result 1, ACCEPT**; `a=5 b=3` → **result 0, ACCEPT**; an operand ≥ 2³² → **loud REJECT** (`out of provable range`), never a silent wrong proof. Soundness gate still **13/13**.
- **Rope 4 — stack overflow (a crash, not slowness).** The prover walks m=32n-element codewords by non-tail recursion; at the gadget's circuit size (n≈1024, m≈32768) that's 32768 C frames and the proof **segfaulted**. Fixed by linking the native binary with a 512MB stack (`-Wl,-stack_size,0x20000000`, the arm64 max; clang-only, the GCC fallback omits it).
- **Rope 3 — pervasive O(n²) cons-list indexing.** The prover indexed codewords/cosets by position with `wnth`/`nth2` (O(n) cons-walks) **inside per-element loops over m** → O(m²) everywhere (`trace_leaf_lro`, `build_q_b3`, `build_b_b3`, `eval_g2_on_dom`, `fold_at2`, `sqd`, …). A comparison proof spent >18 min there. Fix: a new **O(1)-indexable vector** primitive (`to_vec`/`vget` — native flat array, interpreter uses the already-O(1) Python list; difftested [`vget_difftest.glass`](examples/prove/vget_difftest.glass)) plus lock-step walks, applied across the hot loops; `build_q_b3` also now LDE's the 6 permutation columns once (NTT) instead of `poly_eval_b` per point. Result: **>18 min → ~54s** (and the full demo **1m04s → 38s**).
- **Two real bugs, caught by the gates.** (1) The NTT butterfly add overflowed u64 (Goldilocks p≈2⁶⁴) — the interp≠native difftest flagged it; fixed with `__int128`. (2) Growing glassc.glass's C-runtime preamble (Poseidon/NTT/vget intrinsics) pushed its ~290-deep `++` chain past **clang's frontend recursion limit** when compiling the self-hosted compiler — `cc` segfaulted and the **bootstrap fixpoint broke**. Fixed by splitting `c_prelude_of` into 7 shallow sub-functions (≤45-deep each); **fixpoint re-verified** gen1==gen2 (1117 lines C). Suite **407/407** (+vget guard).
- **Honest status.** The gadget *lands* and is *sound*, at ~54s (≈22s of that is clang recompiling the 150KB driver each invocation; the ~32s proof is now legitimate O(m log m) work over the 32768-domain — the O(n²)/O(n³) ropes are gone from the profile). It is not yet under the 30s target; the remaining lever is unboxing the field through the codeword layer (avoiding the boxed-limb↔word conversions `lde` does per call) — a larger change with diminishing returns.
