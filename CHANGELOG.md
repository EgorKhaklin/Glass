## [5.134.0] — 2026-06-12 — Substrate: the Goldilocks fast reduction lands; the profiler names the real ceiling (GC)
- **Every unboxed Goldilocks operation paid a generic 128-bit division** (`__udivmodti4`) for its `mod p` — including each of the thousands of multiplies inside every Poseidon2 permutation, the NTT butterflies, and the F_{p²} tower. All 22 sites in the native C prelude now use the **branch-light fast reduction** for p = 2⁶⁴−2³²+1 (the standard trick: `x ≡ lo + hl·(2³²−1) − hh`, two bounded wrap-fixes, one conditional subtract). It returns the **same canonical value as `% P` for every 128-bit input** — unit-tested against the generic reduction on 20M random + 15 edge inputs — so every proof is **byte-identical** (verified by regenerating corpus fixtures and comparing bytes); the change is invisible to both verifiers, the corpus, and the Name lineage semantics.
- **Honest measurement: no end-to-end wall-clock win yet — and that finding is the deliverable.** `__udivmodti4` vanished from every profile sample (was up to ~44% of one phase window), but `a<b` still proves in ~60s because the substrate ceiling is **allocation: the Boehm GC is 75–85% of every sample** (boxed `List<Int>` field elements churning through the codeword layers), with strcmp tag-dispatch at ~8%. The profiled conclusion now recorded in the roadmap: the substrate-performance lever (#6) is **unboxing the hot layers**, for which this reduction is the groundwork (once values live in u64 arrays, field ops run at register speed instead of re-becoming the bottleneck).
- The bootstrap fixpoint holds with the new prelude (gen1/gen2 emit 1,167 lines of identical C); difftest + corpus_check 8/8 green; suite **487/487**; Name re-rooted (`d0d08737…`). Also: the README and audit-facing docs were redesigned/reconciled this release cycle (see the docs commits). Research/educational-grade, UNAUDITED.

## [5.133.0] — 2026-06-12 — The verdict is now in the exit code: `glass prove` exits 0 ACCEPT / 1 ABSTAIN / 2 REJECT / 3 DIVERGENCE
- **`if glass prove ...; then` used to treat a REJECT as success.** The CLI printed `proof:   REJECT` but exited 0 — a script (CI job, pre-commit hook, pipeline) branching on the exit code silently passed disproofs. The full contract, documented in `glass help`: **0 = ACCEPT**, **1 = ABSTAIN** (Glass refused to lower; also any infrastructure error), **2 = REJECT** (`verify_b3` ran and the proof failed — e.g. a false `--claim`), **3 = Third-Witness DIVERGENCE** (`--cross-check` only, from v5.132; takes precedence over 2). The verdict line is printed by the *generated driver*, so the prove path now always captures-and-relays the run output (the verdict block prints at the end of a run anyway — nothing is lost).
- The wrong-claim suite gate now pins `rc == 2` on the REJECT path (the 13 other REJECT gates keep their text asserts — same behavior, double coverage). `--emit`/`glass verify` are untouched (`verify` already exited 0/1). Baby Bear legacy path untouched (contract documented for the default Goldilocks). Suite **487/487**; bootstrap fixpoint byte-identical; Name re-rooted (`3267c058...`). ## [5.132.0] — 2026-06-12 — Soundness fix: call inlining no longer captures — `gcd(48,18)` proves 6, not 18 (and a Third-Witness DIVERGENCE is now a hard failure)
- **Closes the wrong-lowering the v5.131 gating uncovered.** The bridge's `inline_fn` bound call arguments as a *sequential* ELet nest — `ELet(p1, arg1, ELet(p2, arg2, body))` — so an argument expression referencing an **earlier parameter's name** was captured by the just-bound parameter instead of the caller's variable. In Euclid's `gcd(b, a % b)` the `a` inside `a % b` resolved to the freshly bound `a` (= the caller's `b`), computing `b % b = 0` → the next level saw `b == 0` and returned one level early: the circuit **attested `gcd(48,18) = 18`** while the source computes **6**. heval and cgen both consume the captured unroll, so the proof was STARK-valid-but-wrong — the lowering-gap class **only the Third Witness sees**, and it did (`--cross-check` flagged DIVERGENCE). The same capture existed in the **fn namespace**: a later argument calling a name an earlier fn-parameter shadows resolved through the extended fenv (`ap(k, f(3))` inlined `f(3)` as `k(3)`).
- **The fix is two-phase, capture-avoiding binding** (`inline_fn` → `inline_go`): every value argument is unrolled against the **caller's** fenv and bound to a reserved temp (`q9p_<param>`), then all parameters are aliased to their temps — `ELet(q9p_p1, arg1, ELet(q9p_p2, arg2, ELet(p1, q9p_p1, ELet(p2, q9p_p2, body))))`. fn-arguments and record types (`addrec`/`rtype_of`) also resolve against the caller fenv. An ELet binds **wires, not gates**, so capture-free programs lower to the *identical* gate stream — verified empirically: regenerating the call-bearing corpus fixtures (`honest_record`, `honest_str_eq`) is **byte-identical** to the committed proofs. **`gcd(48,18)` now proves `6` ACCEPT with the Third Witness AGREEing** (the showcase's header is finally true end-to-end), the fn-namespace shape proves `8` (`k(f(3))`), and the full divmod/HOF/record/computed-callee battery is green.
- **A detected DIVERGENCE is now loud.** `glass prove --cross-check` used to *print* the Third Witness's DIVERGENCE verdict and **exit 0** — a production caller scripting the CLI could miss the one signal that the proof, though STARK-valid, attests the wrong function. All three divergence paths (scalar, string, tuple/record) now **exit 3**. Two new suite gates pin both behaviors: the capture shape `g(b, a-b)` proves 307 + AGREES (rc 0), and a **regressed-capture bridge copy** (via the v5.131 `GLASS_BRIDGE_DIR` hook, `tmpn` → identity) reproduces the old wrong 300, is flagged DIVERGENCE, **and exits 3**. Suite **487/487**; bootstrap fixpoint byte-identical; difftest + corpus_check 8/8; Name re-rooted (`24cdebad…`). Research/educational-grade, UNAUDITED.

## [5.130.0] — 2026-06-09 — Soundness fix: a value wider than its layout slot no longer mis-offsets the next field (audit hole B closed)
- **Closes the third and last hole the v5.128 soundness audit found** (after the v5.129 `substring`/claim fixes), completing the sweep. The prove bridge lays each constructor/record/tuple field at a **fixed slot width** `twidth(t, 12)` and reads the next field at `off + that width`. But a value can be **wider than its slot**: `twidth` decrements its recursion fuel per nesting level while *construction* pads at a flat fuel 12, so a recursive-ADT value over-runs its slot (e.g. `Cons(7, Nil)` = 27 wires vs `twidth(IntList)` = 25). When such an over-wide value is **followed** by another field, that field was read at a shifted offset — onto the overflow wires — and the circuit silently attested a **wrong** value. `second(MkPair(Cons(7, Nil), inp))` proved `0` instead of `inp`; **caught only by `--witness3`**.
- **Fix = ABSTAIN on a *non-last* over-width field** (`assert_field_fits` in `cgen_fields`/`heval_fields`/`seval_fields`, all three lineages). The misalignment only corrupts a *following* field, so an over-wide field is tolerated when it is **last** — which is why the common head-reading fold is unaffected: `map_prove`'s recursive `Cons` tail is always last, so it still ACCEPTs `result: 13`. A recursive (or otherwise variable-width) field placed *before* another field now ABSTAINs with a message pointing to the fix (put the variable-width field last).
- **Also closes the String-field-in-aggregate sibling.** `twidth`'s catch-all returned `1` for a `String` field, but a string is multi-wire (one wire per codepoint), so a `String` embedded in a record/ADT/tuple was laid out in a 1-wire slot — `getn(Box { s: "hello", n: inp })` read a codepoint of `"hello"` as `n`, proving `101` not `inp`. `twidth` now **ABSTAINs** on a `String` field (it has no fixed type-determined wire width); standalone `String` inputs/results are unaffected (`private_prefix`/`private_email`/`reveal_prefix` still ACCEPT + AGREE). 
- This is the make-it-**safe** discipline (as in v5.128/v5.129): a recursive ADT with a trailing field, or a String embedded in an aggregate, genuinely cannot be laid out in a fixed-width buffer correctly, so the bridge refuses rather than silently proving a wrong value — it does not yet *support* those layouts (that would need fuel-threaded layout, a larger change). Two new ABSTAIN gates; the Int-record/recursive-fold proofs are byte-identical (the guard is a no-op for every well-fitting layout). Suite **487/487**; bootstrap fixpoint byte-identical; difftest + corpus_check 8/8 honest-ACCEPT + tamper-REJECT; Name re-rooted (`b4e959bb…`). **The v5.128 audit's three holes (A substring over-read, B layout overflow, C vacuous claim bind) are all closed.** Research/educational-grade, UNAUDITED.

## [5.129.0] — 2026-06-06 — Soundness fix: out-of-bounds `substring` no longer over-reads (an attacker-reachable wrong-ACCEPT)
- **Closes the most severe of three holes a soundness audit found** (a read-only 47-agent sweep for siblings of the v5.128 `ctag` silent-default). `glass prove` on an out-of-bounds `substring` **over-read** the operand: `substring(s, 0, 5)` on a 2-char `s="ab"` lowered to a 5-wire slice whose out-of-bounds tail took the slice helper's default — **wire index 0 = the first input codepoint** — so the circuit attested `"abaaa"` and the **SOUND** `verify_b3` ACCEPTed it, while the source semantics (`glass.py b_substring`, which clamps) compute `"ab"`. Caught only by `--witness3`. **Attacker-reachable:** a predicate like `substring(key, 0, 8) == "sk-live-"` (the headline private-prefix/allowlist proof shape) could be made to ACCEPT for a key that does not satisfy it.
- **The fix reproduces the reference semantics exactly.** A new `substr_bounds(l, h, n)` helper mirrors `b_substring`: a negative or inverted (`start > end`) index **ABSTAINs** (the reference raises); otherwise **both bounds clamp to the value width** and the slice is `[a, b)`. Applied at all three lowering sites (`cgen_strfn`, `heval_strfn`, `seval_strfn`) so the circuit value **equals** the reference for every input — the Third Witness now AGREES on `substring("ab", 0, 5) = "ab"`. In-bounds slices are byte-identical (the private-prefix/email/allowlist showcases are unaffected), and `nthI`/`slwi`/`slw` are untouched (their out-of-bounds→0 is correctly relied on elsewhere for trimmed bignum limbs).
- **Also fixes a sibling vacuous-bind** (audit hole C). `build_claim_m`/`build_claim_pub` (the **scalar** claim binders) bound `vhi(outws)` with no width guard; an **empty** `outws` makes `mks(vhi([])=0, 0)=0` — a vacuously-satisfiable bind that ACCEPTs an arbitrary `--claim`. Both now require `ilenI(outws) == 1` (mirroring `build_claim_mw`'s existing length guard) and ABSTAIN otherwise. The known trigger (`substring("", 5, 2)`, `start>end`) is already closed by the substring fix; this guard is the durable defense in depth.
- **Audit hole B is recorded, not yet fixed** (deliberately separate, broad blast radius): a recursive-ADT value can be *wider* than its static `twidth` (so a field following a recursive field mis-aligns onto a pad wire → reads 0), and `twidth`'s `_ => 1` mis-lays-out a `String` field embedded in a record/ADT. Both are silent wrong-ACCEPTs caught only by `--witness3`; the fix (ABSTAIN on over-width + on no-fixed-width field types) touches the shared layout layer and warrants its own gated pass. See the roadmap. Suite **485/485** (+2 substring-soundness gates); bootstrap fixpoint byte-identical; difftest + corpus_check 8/8 honest-ACCEPT + tamper-REJECT; Name re-rooted (`30bbd1a7…`). ## [5.128.0] — 2026-06-06 — Soundness fix: a built-in list threaded into a proof now ABSTAINs (no silent proof-of-0)
- **Closes a silent-wrong-lowering hole found while building B2.** `glass prove` on a program that threads a **built-in `List<Int>`** through a function and indexes it — e.g. `idx0(dbl(dbl([3, 5, 7])))` — used to emit a STARK-valid proof of **`0`** and **ACCEPT** (the correct answer is `12`), caught only by `--witness3` (DIVERGENCE). The bridge's rule is to **ABSTAIN, never silently prove a wrong value**; this restores it.
- **Root cause.** prism desugars list literals `[a, b, c]` and patterns `[]` / `[h, ...t]` to `Cons` / `Nil` `ECtor`/`PCtor` nodes — but the built-in `List` type is in **no `TypeDecl`** of the proven source (only user-declared ADTs are). The bridge's `ctag` returned `0` for an unknown constructor and `ctor_argtypes` returned `[]`, so **both `Cons` and `Nil` collapsed to tag 0 with dropped fields** → every list pattern matched the first (`[]`) arm → the proof attested the empty-list arm's value (`0`).
- **The fix is the bridge discipline, generalized.** `ctag` and `ctor_argtypes` now **ABSTAIN loudly** on *any* constructor absent from every `TypeDecl`, instead of defaulting to tag 0 / no fields. This is purely corrective: a correct proof requires every constructor to resolve, so it never reached the base case — only the silent-wrong path did. A built-in list (or any undeclared constructor) in proven position is now refused with a clear message pointing to the declared-ADT workaround (`type IntList = | Nil | Cons(Int, IntList)`, as in `map_prove.glass`).
- **Faithful-lowering is preserved end to end.** Declared-ADT proofs are unchanged: `map_prove.glass`'s `IntList` (Nil/Cons) still resolves and ACCEPTs `result: 13`. New suite gate asserts the built-in-list program ABSTAINs (`verdict: ABSTAIN`, "undeclared constructor", **no** ACCEPT); the refusal fires during lowering (pre-STARK), so it is fast. Suite **483/483**; bootstrap fixpoint byte-identical; difftest + corpus_check 8/8 honest-ACCEPT + tamper-REJECT; Name re-rooted (`c8df2a97…`). (Faithfully *lowering* built-in lists — monomorphizing `List<T>` to the ADT machinery — remains a separate, roadmapped feature; this change makes the unsupported case safe, not supported.) Research/educational-grade, UNAUDITED.

## [5.126.0] — 2026-06-06 — H3 building block B1: authenticated FRI fold (membership + fold in one circuit)

## [5.124.0] — 2026-06-05 — Merkle-path dedup, Stage 1: batched trace openings (proofs ~15–43% smaller)
- **The three trace Merkle trees (LRO, Z, quotient) are now opened as a BATCH multiproof** instead of one independent sibling path per query. The 82 queries share most high-level path nodes; a batch sends each distinct node once, and the verifier *reconstructs* each root from the opened leaves + a minimal co-path. Soundness-neutral (the proof *data* is the same; the opening encoding is denser). Measured: the representative comparison proof `a<b` falls **448,003 → 381,850 tokens (−14.8%)**; `a/b` 501k → 438k (−12.7%); small proofs whose trace trees saturate fall further (`a+b` **126,606 → 71,589, −43%**). This is the first of the two Merkle-dedup stages designed in [`docs/merkle-dedup-design.md`](docs/merkle-dedup-design.md) (Stage 2 — the FRI `bopen`, the larger ~53% lever — is next).
- **This changes the PROOF STRUCTURE, so `verify_b3` itself is in the lockstep** (unlike the v5.122 serialization-only change). ## [5.105.0] — 2026-06-03 — A LogUp range-lookup argument over Goldilocks (the cheap-range frontier, standalone foundation)
- **The prioritized next frontier, founded.** Comparison and division pay ~32 bit-decomposition range-gates per operand (range_k / lt_build) — which is what makes those proofs ~600k tokens. The cheaper, wider replacement every modern STARK uses is a **lookup**: prove `a ∈ [0, 2^k)` by a table lookup, not bit-decomposition. [`examples/frost/frost_logup.glass`](examples/frost/frost_logup.glass) builds the sound core — a **LogUp (log-derivative) range-lookup argument** over Goldilocks — as a standalone, dogfooded Frost component: `Σ_j 1/(β − a_j) == Σ_i m_i/(β − T_i)`, the values on the left, the dense table `T_i = i` with multiplicities `m_i` on the right, β a Fiat-Shamir challenge. By partial-fraction uniqueness the two rational functions are equal iff `{a_j}` is exactly the multiset `{i with multiplicity m_i}`, so by Schwartz–Zippel a wrong claim passes only with probability ≤ `(2^k − 1)/|field|`.
- **Designed + adversarially red-teamed before a line was written** (a multi-agent design panel, in the discipline that proved the v5.96 sign-bit `sdiv` design unsound). The panel caught the crown-jewel trap: if the "table" were the prover's *observed distinct values* (a sparse support), an out-of-range value (say 16) would appear as a pole on **both** sides — `1/(β−16)` and `m_16·1/(β−16)` — and **cancel at every β**, so `[3,7,16]` would be wrongly ACCEPTED (the sparse form proves only `values ⊆ support`, never `support ⊆ [0,2^k)`). The fix is non-negotiable and is what shipped: a **DENSE literal table** `{0..2^k−1}`, so an out-of-range value has no canceling partner. β is drawn from **F_{p^2} ≈ 2^128** (not base 2^64: the error is `(2^k−1)/|field|`, so the base field gives only ~`64−k` bits — below target; F_{p^2} gives `128−k`, past 80 for k≤32), and a **degenerate β** (zero imaginary part → a base-field denominator could vanish) **ABSTAINs** rather than divides.
- **Sound, int64-safe, dogfooded.** Seven cases, byte-identical under glass.py (bignum) and native_glassc (int64): honest in-range `[3,7,7,0,15]` → **match (ACCEPT)**; out-of-range `[3,7,16]` → **no-match (caught)**; a forged multiplicity (over- or under-count) → **caught**; duplicate-heavy `[5,5,5,5]` → match (LogUp counts multiplicities); empty → vacuous ACCEPT; degenerate β → **ABSTAIN**. No new field primitive — a pure client of the `frost_goldilocks_ext.glass` F_{p^2} toolkit.
- **Honest scope + the path forward.** This establishes the LogUp range-check *mechanism* (sound by Schwartz–Zippel + partial-fraction uniqueness, dogfooded) — it is **not** an in-circuit argument. Wiring it into the bridge's `range_k`/`lt_build` is the known multi-session, soundness-critical step: a **constrained running-sum column** (a boundary + transition quotient binding it to the wires — the sibling of the PLONK grand-product `Z`, NOT a host-side check) with **advice-pinned multiplicities**, landed in lockstep in **both `verify_b3` and the independent Pentecost verifier**. The red-team's second finding — an unconstrained running-sum column lets a prover commit `S = 0` and certify anything — is exactly the integration hazard that step must close, and is recorded.
